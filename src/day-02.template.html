01 Getting Started · Boolean Logic · Arithmetic

先留出未知的位置，
再告诉程序哪些值可以用。

在 Day 1 的演示中，你亲手给物体的位置和角度赋值。现在可以把房间的位置先留成未知数，例如 x_A、y_A，然后写下“必须在边界内”“不得重叠”。求解器寻找的是一组让这些要求同时成立的取值。

把新词对应到两个房间的例子
术语在这里指什么例子
变量暂时未知、希望确定的量A 的左下角横坐标 x_A
变量的类型／取值域允许用哪一类值整数 Int、实数 Real、真假 Bool
约束／断言必须成立的公式；加入求解器后称为断言x_A ≥ 0
模型 model使当前断言都成立的一组解释或赋值x_A = 0, y_A = 0
可满足 satisfiable至少存在一个模型找到一种完整满足要求的摆法

这里的 model 是一组满足公式的解释，和“训练一个神经网络模型”不是同一个用法。一个问题可能有很多模型；普通 Solver() 找到一个即可，没有自动承诺它最漂亮、最省面积或最方便通行。

动手看

把范围设为 2.2 ≤ x ≤ 2.8，比较实数与整数。再把上界移到 3：究竟是公式变了、变量类型变了，还是出现了新的允许值？

SAT 与 SMT，在解决哪一类问题？

SAT 关心布尔公式：能不能给若干命题分配“真／假”，使整个逻辑式为真？例如“门已解锁”与“机器人有权限”都为真，某个通行条件才成立。

SMT 在逻辑连接词之外，还让整数、实数等对象遵守相应数学规则。例如它要理解 x ≥ 2 和 x ≤ 1 对同一个数不能同时成立。Z3 是支持多种理论与求解接口的工具；你仍然需要把场景要求翻译成公式。

And(A, B)A 与 B 都要成立
Or(A, B)A、B 至少一个成立，也可都成立
Not(A)A 不成立
Implies(A, B)若 A 成立，则要求 B 成立
用你熟悉的 Python 看一个最小 Z3 例子
from z3 import Int, Solver, sat, unsat

x = Int("x")                 # 数学整数变量；此时还没有给它取值
s = Solver()
s.add(x >= 2, x <= 4)       # 这两条必须同时成立
result = s.check()
if result == sat:
    print(s.model())         # 查看本次找到的一组满足赋值
elif result == unsat:
    print("当前约束不可同时满足")
else:
    print("尚无法判定：", s.reason_unknown())

s.add(a, b) 同时加入 a 与 b；需要“至少一个”时写 s.add(Or(a, b))。组合 Z3 符号公式时使用 And/Or/Not，避免把 Python 的 and/or/not 当成符号逻辑连接词。

停一下，自己解释：把米坐标从 Real 改成 Int，只是显示格式变化吗？

它改变了允许的位置。以米为单位的 Int 只允许整数米坐标。若用整数厘米，需要把全部尺寸与阈值统一换成厘米。不能用整数网格中没找到解，直接断言连续坐标中也无解。

来源：Z3Py 官方入门：Getting Started、Boolean Logic、Arithmetic、Solvers。

02 把中文要求逐条形式化

不重叠：只要在一个方向上分开。

先限定今天的模型：房间是轴对齐矩形，边始终平行于 x、y 轴，不允许转斜；宽高都是正数，位置记在左下角，单位为米。A 的横向范围是 [x_A, x_A + w_A]，纵向范围是 [y_A, y_A + h_A]。

第一组：完整放进外框

外框宽 W、高 H，左下角在原点。对每个房间 i，都需要下面四条同时成立：

xi ≥ 0　∧　yi ≥ 0
xi + wi ≤ W　∧　yi + hi ≤ H

只检查左下角在外框里会漏掉伸出去的右边与上边。这也是为什么要先说清楚“坐标记在中心还是左下角”。

第二组：两个房间的内部不相交

把两张纸片放在桌面上。它们可以一左一右分开，也可以一上一下分开。只要其中一种分离关系成立，就不会出现内部重叠。

动手看

先选左右贴边，观察哪一项为真；再选上下分开。最后切换 Or 与 And，解释为什么“上下已经分开”时，并不需要“左右也分开”。

下面把两间房的宽高暂时都固定为 2，并用 Real 声明连续坐标，单独构造这条非重叠公式：

from z3 import Or, Reals

xA, yA, xB, yB = Reals("xA yA xB yB")
wA = hA = wB = hB = 2
no_overlap = Or(
    xA + wA <= xB,   # A 在 B 左边
    xB + wB <= xA,   # B 在 A 左边
    yA + hA <= yB,   # A 在 B 下边
    yB + hB <= yA    # B 在 A 下边
)
print(no_overlap)

外框要求与非重叠要求之间是 And；四个分离方向内部是 Or。如果把四项全部写成 And，你会同时要求“A 完全在 B 左边”和“B 完全在 A 左边”，正宽度的两个房间不可能满足。

这里使用 ≤，所以允许贴边。若需要非负间隔 g ≥ 0，就在对应分离项中加上 g，例如 xA + wA + g ≤ xB。间隔代表哪个实际要求、是否允许为零，应在建模时先确定。

为什么这个四向条件没有漏掉其他轴对齐情况？

两个正尺寸轴对齐矩形内部重叠，当且仅当它们的 x 区间有正长度重叠，而且 y 区间也有正长度重叠。要让内部不重叠，只需至少一个轴上的内部区间分开；每个轴有两个先后方向，合起来就是四项。旋转矩形、非矩形轮廓不直接适用这条 AABB 公式。

停一下，自己解释：只验证 x 方向，可能会犯什么错？

如果强制必须左右分离，会错误拒绝原本可以上下排开的合法摆法。完整条件要保留两个坐标方向。

来源：Day 2 空间约束任务；逻辑语法见 Z3 Guide · Boolean Logic。区间推理与交互为本教程的解释。

03 用反例理解 UNSAT

面积 9，为什么容不下总面积 8？

给两个房间都固定为 2 m × 2 m，外框取 3 m × 3 m。总面积确实足够，但几何摆放还必须满足每个方向的尺寸关系。

动手看

保持高度 3，把宽度从 4 拖到 3。接着保持宽度 3，把高度改到 4。观察合法见证如何从左右摆放变成上下摆放。

先试着证明 3×3 无解，再展开分步解释
  1. 每个宽 2 的房间都要留在宽 3 的外框里，所以 0 ≤ xA,xB ≤ 1。
  2. 若 A 在 B 左边，需要 xA + 2 ≤ xB；但左边至少为 2，右边最多为 1，矛盾。左右交换同样矛盾。
  3. 高度也是 3，因此 0 ≤ yA,yB ≤ 1。上下两个分离方向同样都不可能。
  4. 四项 Or 的每一项都不可能成立，所以整组约束不可满足。

这段证明允许任意实数坐标，因此结论不依赖“只试了几个整数位置”。这里的条件全部固定后，面积足够只是必要条件，并非充分条件。

可行见证与无解证明，证据形式不同

证明有解，拿出一个满足全部约束的摆法即可。证明无解，需要排除全部允许的摆法。反复拖动却没摆好，本身不能完成后者。

对于这个特定的“两间固定 2×2”模型，能够放下的条件恰好是：

W ≥ 2　∧　H ≥ 2　∧　(W ≥ 4　∨　H ≥ 4)

尺寸或房间数量变了，就要重新推导或求解。尤其是更多房间的布局，不能直接套用这条两盒结论。

如果让房间面积也成为设计变量呢？

本页把房间宽高固定为 2，位置是未知变量，所以主要使用线性算术与布尔析取。若宽、高都变为未知数，面积约束 w × h ≥ A 包含变量相乘，会改变求解问题的性质。应记录你改了哪些变量、约束和求解设置，并重新检查结果与耗时。

来源：Day 2 的 3×3 反例、原 MiniLab。连续坐标证明为本教程给出的几何推导。

04 从“不重叠”继续走到“有可用接面”

没有撞在一起，
还不代表门接得上。

两个房间可以相隔很远而不重叠。要在它们之间开门，还需要一段真实的共享墙、一个位于墙段内的开口，以及足够的有效净宽。几何关系与 Day 1 的图连通是不同证据。

以 A 在左、B 在右为例，共墙首先要求 xA + wA = xB。共享墙的纵向区间为：

L = max(yA, yB)
U = min(yA + hA, yB + hB)
U > L

U > L 要求有正长度。只碰到一个角时 U = L，没有可容纳正宽门洞的墙段。

动手看

先观察共墙；把 B 稍微移开，制造缝隙；再移到只碰角的位置。恢复共墙后，把门洞移向墙段端点：即使门宽小于整段墙长，也可能放错位置。

门的位置和门的宽度，要一起检查

把门洞中心记为 c、净宽记为 d，它沿墙的开口区间是 [c − d/2, c + d/2]。完整落在共享墙段内，需要：

d > 0
L ≤ c − d/2　∧　c + d/2 ≤ U

如果机器人用一个固定宽度 b 表示，每侧要求留出余量 s，则净宽条件为 d ≥ b + 2s。这只是当前模型中的横向尺寸要求；机器人转弯时的扫掠空间、门扇、门槛与高度还可能引入其他限制。

楼梯接面为什么还要看高度？

俯视图中重叠的区域，可能位于不同高度。图中预定落脚高度为 1.00 m，平台顶面为 0.80 m；即使水平投影有正面积交集，竖直方向仍相差 0.20 m，还没有发生接触。高度对齐与可用接触面积只是候选接触证据，完整支撑、台阶尺寸和身体运动还要继续检查。

数学公式的相等，与测量几何的容差

Z3 的数学整数／实数关系与浏览器几何显示的数值计算要分开。编码里的精确相等要求两个表达式相等；带噪声的测量通常需要事先声明允许误差。后验检查中的容差只能处理已定义的误差范围，不能偷偷把真实缝隙或净宽不足当作通过。当前组件给出自己的数值边界说明。

停一下，自己解释：“门宽小于墙长”足够证明门合法了吗？

还不够。先要有有效共享墙，并检查门开口的整个区间位于共享墙段内。门过窄、门被锁、门后有障碍、机器人无法转弯，分别还涉及尺寸、状态和运动条件。

来源：Day 2 门／楼梯接面任务。门区间公式和平台图为明确建模条件的教学补充。

05 Solvers · Models · reason_unknown

求解器的三个回答，
决定三种后续工作。

先把返回值翻译成一句准确的话
返回值它回答了什么接着做什么
sat当前断言存在模型读取模型，核对编码，再做独立几何与任务检查
unsat当前断言无法同时成立确认输入、单位和模型条件，再研究冲突证据
unknown本次求解没有判定可满足或不可满足保存原因、预算和输入，调整方法后再检验

unknown 不等于 unsat。超时是可能的原因之一，也可能涉及理论或求解能力限制。报告实际 reason_unknown() 返回什么；若它只给出笼统原因，就保留这个限度。

动手看

切换四种已记录的情况，观察流程在哪一步停下。尤其比较“公式有模型”和“公式有模型，但后面的门宽检查拒绝”。

求解成功后，为什么还要检查？

假设公式只描述“两房完整放进外框，且不重叠”。Z3 给出 sat，说明这一组几何要求可满足。若你随后问“宽 0.60 m 的机器人能否通过宽 0.50 m 的门”，这个新问题没有被前面的打包公式回答。

独立检查可以发现模型里遗漏的要求、单位或坐标转换错误、几何接面问题。再往后的路径规划与执行验证，回答的是实际运动能否完成。每一层都应把已检查条件和仍未检查条件写清楚。

一个实际返回 unknown 的例子
from z3 import Real, Solver, sat, unsat

x = Real("x")
s = Solver()
s.set(timeout=3000)    # 时间预算 3000 ms；设置预算不代表实际发生超时
s.add(2 ** x == 3)
result = s.check()
print(result)
if result != sat and result != unsat:
    print(s.reason_unknown())

官方入门用这个非多项式表达式说明求解边界。配套运行记录保留本次 Z3 版本的真实状态与原因；不能把这一次输出推广为所有公式、版本和设置的表现，更不能自行把原因改写成“超时”。

停一下，自己解释：一个无效摆放、一个 UNSAT 问题、一次 UNKNOWN，分别说明什么？

无效摆放：这个候选违反至少一条要求。UNSAT：当前模型中全部允许赋值都无法同时满足断言。UNKNOWN：本次求解没有得出上述两种结论。三者需要不同证据。

来源：Z3 Guide · Solvers、Programming Z3 · Models；实际记录见 运行数据。

06 Incrementality · Scopes · Assumptions

先保留基础条件，
临时试一个新要求。

你常常要比较相似场景：房间宽度不变，暂时加一道门宽限制；或者保持基础关系，试试某个状态。push() 可以开启一个临时作用域，pop() 撤回与它匹配的作用域里新增的断言。

动手看

先 check 基础约束；push 一层后加上 x ≤ 1，再 check；最后 pop 并重新 check。观察哪些断言一起被撤回，哪些基础断言仍然保留。

from z3 import Int, Solver

x = Int("x")
s = Solver()
s.add(x >= 2)        # 基础层
print(s.check())

s.push()              # 记住当前作用域边界
s.add(x <= 1)        # 临时新增的要求
print(s.check())

s.pop()               # 撤回这一层新增的断言
print(s.check())       # 必须针对恢复后的状态重新检查

pop() 不是“删掉最近一条公式”：同一层新增的多条断言会一起撤回。模型和冲突核心要对应最近一次检查时的断言集；改了断言后，重新 check，再读取对应结果。

assumptions：只对这一次检查启用的条件

也可以把可选要求接在一个布尔开关后面。例如 Implies(try_narrow, x ≤ 1) 表示“如果启用这个开关，就要求 x≤1”。调用 s.check(try_narrow) 会在本次检查假设开关为真；假设不会作为一条永久新增断言留在后续普通 check() 中。不传这个开关，表示本次没有要求它为真，并不等于另外断言了 Not(try_narrow)。

“打开条件”的代码，和“只给条件贴标签”有什么区别？

显式 Implies(flag, condition) 搭配 check(flag) 可以按本次假设启用规则；assert_and_track(condition, label) 会让该条件在它所在的作用域内保持启用，同时为诊断提供标签。普通 check 时漏写 track 标签，不会把被跟踪条件关闭。

停一下，自己解释：push 后加两条要求，再 pop，会留下哪几条？

push 之前的基础断言留下；匹配作用域里新增的两条一起撤回。若有嵌套作用域，先退回最上面一层。增量机制帮助复用求解状态，不承诺每种问题都一定更快。

来源：Z3 Guide · Solvers、Programming Z3 §4.1–4.3。

07 assert_and_track · Unsat Core

冲突核心：一组足以冲突的证据。

当要求很多时，只得到 unsat 还不容易知道该从哪里检查。你可以为条件贴标签，在最近一次 check 返回 unsat 后，读取 unsat_core()，得到一组与该次不可满足有关的跟踪标签或假设。

门宽的两条要求

minimum_clearance: d ≥ 0.8 与 available_opening: d ≤ 0.5 不能同时成立。它们指出一个兼容性问题：需求下界高于几何上界。仅凭这个结果，不能判断哪一条记录是错的，也不能决定应该牺牲哪项真实要求。

动手看

先选择 x 的两条冲突，再选择 y 的两条冲突。把当前全体约束中的一条 x 条件移除，看看 y 的冲突是否还在。然后检查“全部标签”是否也足以无解，却含有多余条件。

标签的粒度，决定你能定位到多细

如果把 A 的四条边界打包成 assert_and_track(And(...), "a_inside")，核心只能告诉你整组边界标签参与了冲突。若每条边界分别贴标签，就有机会定位到更细的断言。核心中的“一个标签”不一定对应“一条原子不等式”。

from z3 import Real, RealVal, Solver, unsat

d = Real("door_width")
s = Solver()
s.assert_and_track(d >= RealVal("0.8"), "minimum_clearance")
s.assert_and_track(d <= RealVal("0.5"), "available_opening")
if s.check() == unsat:
    print(s.unsat_core())

这里用字符串建立精确十进制有理数。涉及分数时，也可以用 Q(1, 3) 等 Z3 表达式，避免先在 Python 中进行浮点运算，再把近似结果误当精确约束。

三个看起来相近、含义不同的“核心”
说法准确含义
一个不可满足核心这组所标条件连同固定背景，已足以不可满足；可能有多余项。
包含极小核心从该核心再删任何一项，就不再是核心。
条数最少的核心在所有核心中，包含的标签数量最少；这是更强的要求。

默认返回的核心不保证唯一，也不保证极小或条数最少。“存在两个不同核心”也不等于某个求解器每次运行必然轮流输出它们。最小化设置、标签分组和求解流程都会影响你能得到的诊断。

有未跟踪背景约束时，核心要和什么放在一起理解？

设未跟踪的固定背景是 B，返回的标签对应条件 C。保证的是 B ∧ C 不可满足，而不是 C 单独必然不可满足。若 B 自己已经矛盾，返回空核心也可能合理。因此记录核心时，还要保存背景断言、标签映射、本次 assumptions 和版本。

停一下，自己解释：从一个核心里去掉一项，就一定把整个问题修好了吗？

不一定。若这个核心不是极小的，剩余子集可能仍然冲突；即使它被打断，全体约束中还可能有另一组独立冲突。更根本的是，核心给出逻辑证据，不负责决定允许修改哪些需求。应先检查输入和编码，再在获准改变的条件范围内提出方案。

来源：Programming Z3 §4.3–4.4；真实标签粒度对照与两个独立冲突见配套实验。

08 Solver · Optimize · 分级退让

先满足必须做到的事，
再比较哪种方案更合意。

“房间必须留在外框内”“门洞至少有要求的净宽”可以作为硬约束。而“门宽尽量接近期望值”“房间尽量靠窗”可以作为偏好或优化目标。它们是否允许让步，要由需求定义，求解器不会自行知道。

普通 Solver 判断可满足并找模型；Optimize 可以在保留硬约束的同时，通过最小化／最大化目标、或带权软约束比较方案。Z3 包含优化接口，因此“Z3 和优化器完全无关”也是误解。

动手看

先观察候选门宽怎样被硬要求筛选，再调整偏好。把可用宽度收紧到低于最低净宽，看看只改变期望门宽能否恢复可行。

分级退让，要把改动对象写出来

  1. 先保持硬要求。核对坐标、单位和是否写错连接词。
  2. 再调整已允许让步的偏好。例如降低某个软目标的优先级，记录“改了哪个目标”。
  3. 仍无解时，回到需求层讨论结构性改动。例如扩大外框或改变任务设定；它们属于问题条件变化，不能装作原条件已经被满足。
  4. 对修改后的结果重新检查。保留原输入、新输入、变更原因与检查结论。

若真正的硬约束自身已经冲突，仅仅改变优化权重，不能凭空产生满足这些硬约束的模型。

停一下，自己解释：“找到了一个模型”和“找到了最优模型”差哪一步？

前者只要求模型满足当前断言；后者还要明确候选空间、目标函数、目标之间的优先方式和求解结果。没有指定的目标，“更好”没有可计算的含义。

来源：Programming Z3 §8 Optimization、Day 2 分级退让与后验验证要求。
