# Day 06 · 从可渲染场景到机器人训练环境

Day 6 的核心不是“会不会打开 Isaac Sim”，而是能否把 **UE 场景资产、物理仿真世界、机器人学习任务、评测证据** 这四件事分清楚，并写成一份可交接的合同。

## 一条最重要的链

`UE/PCG Mesh → 尺度与坐标 → Collision/Rigid Body → Joint/Articulation → Sensor → Observation → Policy → Action → Controller → Physics → Reward/Termination → Reset → Episode metrics`

任何一步缺失，都不能只凭“场景看起来能跑”宣布它已经是机器人训练环境。

## 三个责任方（谁生产、谁消费、不负责什么）

| 层 | 生产 | 消费 | 不负责 |
|---|---|---|---|
| UE / PCG | 视觉网格、材质、灯光、布局、门动画 | 美术与关卡意图 | 物理正确性、观测公平性 |
| Isaac Sim | 刚体、碰撞、关节、接触、传感器采样 | USD 资产 + 物理参数 | 任务定义、训练循环、评测口径 |
| Isaac Lab | observation / action / reward / termination / reset 接口 | 物理世界状态与采样 | 资产建模、求解器精度 |

链条是 **UE 资产 → USD → 物理世界 → 任务接口 → 训练/评测**，箭头不是自动完成，每一段都要显式交付信息。

## 16 个核心问题（对应页面 16 个小节）

1. **责任分工**：资产、物理、任务三层不能互相甩锅。门推不开先查 articulation，再查 action 通道，最后才怀疑策略。
2. **渲染几何与物理几何**：视觉 Mesh 可以没有碰撞；任务必须有 collision、尺寸、净空、footprint。
3. **质量、摩擦与时间步**：同样推力在不同 mass、friction、步长下响应完全不同。
4. **门的 Articulation**：门有动画 ≠ 有 hinge joint。要查 joint 类型、轴、限位、drive/阻尼。
5. **Observation 公平性**：策略只能读合同声明的观测；直接读 `door_locked` 这类现实不可测真值属于特权观测。
6. **时间同步**：物理、传感、控制各有自己的钟，需要写清采样、保持、延迟与时间戳。
7. **Action 合同**：变量、单位（m/s、rad/s）、频率、限幅、安全边界，缺一项就不可执行。
8. **Reward 与 Success**：奖励是训练信号，成功是评测谓词。奖励高仍可能没完成任务（空车冲终点）。
9. **Reset 完整性**：位置之外还要恢复速度、关节、物体、随机状态、seed 记录。
10. **Seed 与数据划分**：训练/测试 seed 重叠会把“记住场景”误当“学会任务”。
11. **UE → 仿真审计**：19 项逐条核对（见下）。
12. **三个反例**：症状 → 缺哪个接口 → 如何独立验证。
13. **checker 与 rollout 的差距**：规则校验能判“布局合法”，判不了“能否做成”。
14. **Episode 时间线**：reset → observation → policy → action → physics → reward/termination → 下一帧观测。
15. **综合考题六栏答卷**：输入/假设 → 方法/接口 → 预测 → 实际证据或未实测 → 可能失败 → 下一步。
16. **写成任务合同**：scene / robot / observation / action / task / 复现 / 证据边界。

## 迁移审计（19 项，每项标“谁生产 / 单位 / 谁消费 / 缺失后果”）

1. 世界尺度（米，1 m = 100 cm）
2. 世界原点与轴方向（右手系、Z 向上）
3. 资产姿态约定（旋转顺序、万向节顺序）
4. 碰撞体 collision（凸包或盒体）
5. 门洞净宽与净空（米）
6. 机器人 footprint（半径或长宽，米）
7. 质量 mass（kg）
8. 惯量 inertia（kg·m²）
9. 摩擦与恢复系数（无量纲）
10. 关节类型（revolute / prismatic）
11. 关节轴与限位（轴向量、弧度）
12. 关节驱动 drive（刚度、阻尼、力矩上限）
13. 传感器外参（相对位姿，米 / 弧度）
14. 传感器时序（Hz + 时间戳）
15. 噪声与遮挡模型（标准差、遮挡概率）
16. action 单位与频率（m/s、rad/s、Hz）
17. reset 恢复范围（全部动态状态）
18. success / termination / timeout（谓词 + 秒）
19. seed 与场景版本（整数 seed、资产版本号）

“USD 导入成功”只说明文件能读，不证明以上任何一项正确。

## 三个必须会讲的反例

**反例 1：视觉墙没有碰撞。**症状是机器人穿墙、规划穿墙路径；缺的是 collision geometry；验证用射线/接触查询或让机器人撞一次墙，而不是看截图。

**反例 2：门有动画却没有物理铰链。**症状是序列里门会开、机器人推不动；缺的是 articulation（joint 类型、轴、限位、drive）；验证是读该门的 joint 数量与类型，为 0 就只是动画。

**反例 3：策略读取 `door_locked` 真值。**症状是仿真成功率极高、实机立刻崩；缺的是 observation 公平性约束；验证是逐字段问“实机能否测到”，并把真值换成传感器估计再测。

反例 3 最危险：前两个会当场暴露，第三个不会报错，只会让指标变好看。

## checker 与 rollout 的差距

| 问题 | 规则 checker | 物理 rollout |
|---|---|---|
| 物体在房间内、互不重叠 | 能 | 仍需满足 |
| 门在墙上、净宽 > footprint | 能 | 可过 ≠ 真能过 |
| 出生点没被占用 | 能 | 仍需检查是否卡住 |
| 推门时接触与摩擦 | 不能 | 只有接触求解能判断 |
| 加噪后观测是否可用 | 不能 | 只有采样能判断 |
| reset 后状态是否一致 | 不能 | 只有对比两次 reset 能判断 |

只有 checker 时永远只覆盖 3/6——换 seed 也不会变，这不是样本量问题，是能力问题。

**没有 Isaac 的替代协议**：① 冻结场景与 seed → ② 写状态表（reset 后每个对象的位置/速度/关节角）→ ③ 纸面 rollout（按控制周期推演）→ ④ 标注未实测 → ⑤ 给出失败判据。

## 六栏答卷（今日综合考题）

问题：一个 UE5 PCG 场景能播放、门有动画，能不能直接说是 Isaac Lab 训练环境？

1. **输入 / 假设**：资产清单、单位、门是动画还是机构、机器人模型来源；“我不知道”也要写。
2. **方法 / 接口**：缺 collision / articulation / observation / action / termination 中的哪些，点到字段。
3. **预测**：穿墙、推不开、观测超前、指标虚高——写可观察现象。
4. **实际证据或未实测**：哪条亲眼验证过，哪条只是推演。
5. **可能失败**：你的判断错在哪，反证条件是什么。
6. **下一步**：一次最小验证动作（读 joint 列表、做接触查询、跑一个 episode 并记 seed）。

## 五维自评（0–4 分）

概念 / 因果 / 工程接口 / 验证 / 经历真实性。今天只读文档就是“只读了文档”；能设计契约但没跑实例是“合同设计”；声称跑过就必须拿得出场景版本、seed、观测、动作、终止日志，拿不出就退回上一档。

## 交给 Day 7 的字段

`episode_id`、`scene_id + 资产版本`、`seed`、reset 后初始状态、observation 字段 + 频率 + 时间戳、action 类型 + 单位 + 频率、reward 分项、termination/success/timeout、策略版本、相机内参/外参、失败原因标签、是否人工示范。

缺 `scene_id`/`seed` 无法复现；缺 `termination`/`success` 示范无法标正负；缺 action 单位策略输出无法执行。

## 真实性边界

本教程中的网页与 Python 属于教学模型。没有运行 Isaac Sim、Isaac Lab、ROS 或实体机器人，因此不能把它们写成“仿真成功率”或“实机成功率”。本页练习应标记为**合同设计**，不是已运行实验。
